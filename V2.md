## 1. Purpose & data goals

**Purpose:** analytical. Analyze manga/comics published in Spain, using as source of truth the public curated lists of the Whakoom user **deirdre** — lists organized by *Year* and by *Magazine* (the magazine lists refer to the Japanese serialization magazine; Whakoom itself carries the Spanish publisher).

**Data to collect per series:**

- List name, list membership, and position within each list
- Series name, original title, publisher, authors, synopsis
- Volumes published ("N cómics") or single-volume ("tomo único") status
- Average score, number of votes, star-rating distribution, ownership count ("how many have it")
- Volume list (number, title, publisher, cover)
- URLs and related metadata
- **History:** score/votes/ownership captured per scrape run, queryable over time

**Interpretation guardrail:** Whakoom provides *cataloging and popularity* signals (ratings, votes, ownership counts), **not sales data**. No analysis may present these metrics as units sold or revenue.

**Non-goals:** no private lists, no UI/API, no scheduling/cron, no real-time processing, single user, no image downloading.

## 2. Verified site facts

All facts below were verified against the live site on 2026-08-01 (HTTP probing + browser confirmation).

### 2.1 Access matrix

| Path | Anonymous? | robots.txt | Notes |
|---|---|---|---|
| `/{profile}/lists/` | ✅ | allowed | List cards: name, comic count, description, likes |
| `/{profile}/lists/{slug}_{id}` | ✅ | allowed | First 50 items server-rendered |
| `POST /lists/listdetail.aspx/SeriesPage` | ✅ | site pagination | Plain HTTP + JSON works anonymously |
| `/ediciones/{id}/{slug}` | ✅ | allowed | **All core data lives here** |
| `/publisher/{id}/{slug}`, `/autores/{id}/...` | ✅ | allowed | Publisher/author pages |
| `/comics/...` | ❌ | **`Disallow: /comics/`** | 302 → `/login?ReturnUrl=...` for all anonymous clients, including crawlers |
| `/search`, `/pwkws.asmx/QuickView` (anon) | ❌ | — | 401 |

### 2.2 Consequences

1. **List pagination needs no browser** — it is a single JSON POST (contract in §22).
2. **The series page (`/ediciones/`) is public and complete** — the full analytical dataset is robots-allowed.
3. **List items link to volume pages (`/comics/...`), which are login-gated.** Resolving a list item to its parent series (`/ediciones/{id}/...`) therefore requires an authenticated session. This is the only gated step; see §11.

## 3. Scale & run profile

- ~66 lists, 30–200 items each → **~4,000–8,000 list items**, est. **~2,000–5,000 unique series**.
- Requests per full run: ~150 (lists) + 1 per unique series (resolution, authenticated) + 1 per unique series (ediciones) ≈ **4,000–10,000 requests**.
- At 1 request / 1.5 s: **~2–4 h per full run**.

Design conclusions: synchronous HTTP is sufficient; **every stage must be idempotent and resumable** (long runs will be interrupted); no concurrency machinery.

### 4.3 What is NOT used — and why

| Not used | Reason |
|---|---|
| **Scrapy** | Overkill for 3 page types and one JSON pagination endpoint; adds Twisted, middlewares and settings ceremony for no benefit at this scale. |
| **Selenium / Playwright** | Pagination is a plain JSON POST; browsers add driver management, memory cost, and bypass politeness controls. |
| **SQLAlchemy / any ORM** | Explicit design decision: **SQL lives in `.sql` files as a separate concern from code.** No object-relational mapping anywhere. |
| **Alembic** | Migrations are plain `.sql` files applied in filename order by a small custom runner (see §8.4). |
| **sqlite-utils** | Conflicts with the SQL-files-as-separate-concern design above. |
| **requests / BeautifulSoup4** | Covered by `httpx` / `parsel`. |
| **async (anyio/asyncio)** | Sync-first for determinism and debuggability; the `httpx` API makes async a possible later upgrade without call-site rewrites. |

### 4.4 Database access layer (custom, minimal — this is the design, not a gap)

All persistence uses the **stdlib `sqlite3` module** plus two small custom components:

1. **Named-query loader** (~60–80 lines): reads `store/queries/*.sql`; queries are declared with a `-- name: <query_name>` marker and bound with `?` placeholders **only** — string interpolation into SQL is forbidden.
2. **Migration runner** (~40–60 lines): applies `store/migrations/NNN_description.sql` in filename order, records applied files in a `_migrations` table, wraps each file in a transaction. Forward-only (no down migrations — the DB is rebuilt from scratch).

Rows are returned as `sqlite3.Row` and mapped to dataclasses in explicit repository functions. There is no generic `to_tuple`/`table_name`-style object mapping.

## 6. Coding rules

- Full type coverage; Google-style docstrings on public functions.
- Quality gates: `uv run ruff check .`, `uv run mypy .`, `uv run bandit -r whakoom_scraper/`, `uv run pytest` — all must pass.
- **No silent failures.** Every fetch/parse failure is logged with context and counted in the run record.
- Retry only transient errors (timeouts, 429, 5xx, SQLite busy) — max 3 attempts, exponential backoff. Never retry uniqueness violations, FK violations, missing identifiers, or parse-contract failures: those fail loudly.
- Correctness over speed; determinism over cleverness; explicit over implicit.
- Timestamps are ISO-8601 UTC strings (`strftime('%Y-%m-%dT%H:%M:%SZ','now')`).
- No commits, deletions, or pushes without explicit owner instruction.
- Spanish-locale parsing: decimal commas (`"4,3"` → `4.3`); thousands separators stripped from counts.

## 8. Data model

### 8.1 Identifier discipline (hard rules)

- Surrogate primary keys are always named `id` and never leave the database.
- **Every external identifier carries a `whakoom_*` prefix** (`whakoom_list_id`, `whakoom_series_id`, `whakoom_publication_id`). Mixing namespaces in one column is forbidden — a previous version of this project silently corrupted joins by storing internal PKs and external IDs in the same column.
- Foreign keys reference surrogate `id`s only; natural keys carry `UNIQUE` constraints.
- `PRAGMA foreign_keys = ON` and `PRAGMA journal_mode = WAL` on **every** connection. Single writer per stage process.

### 8.2 Current state vs. history

Each scrape of a series writes **two** things:

1. An **upsert into `series`** — current state, fast to query.
2. An **insert into `series_observations`** — append-only history keyed by run. This is how score/votes/ownership-over-time is preserved. It costs one `INSERT` per series per run and imposes no constraint on the core design.

### 8.3 Schema — `store/migrations/001_initial_schema.sql`

```sql
CREATE TABLE IF NOT EXISTS _migrations (
    filename TEXT PRIMARY KEY,
    applied_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

CREATE TABLE scrape_runs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    stage TEXT NOT NULL,
    started_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
    finished_at TEXT,
    status TEXT NOT NULL DEFAULT 'running'
        CHECK (status IN ('running','completed','failed','aborted')),
    items_processed INTEGER NOT NULL DEFAULT 0,
    items_failed INTEGER NOT NULL DEFAULT 0,
    notes TEXT
);

CREATE TABLE lists (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    whakoom_list_id INTEGER NOT NULL UNIQUE,
    name TEXT NOT NULL,
    url TEXT NOT NULL UNIQUE,
    user_profile TEXT NOT NULL DEFAULT 'deirdre',
    description TEXT,
    comic_count INTEGER,                       -- advertised by the list card
    likes INTEGER,
    list_type TEXT CHECK (list_type IN ('year','magazine','other')),  -- NULL until classified (deferred)
    canonical_name TEXT,                       -- canonical magazine name (deferred enrichment)
    scrape_status TEXT NOT NULL DEFAULT 'pending'
        CHECK (scrape_status IN ('pending','completed','failed')),
    scraped_at TEXT,
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
    updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

CREATE TABLE publishers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    whakoom_id INTEGER UNIQUE,
    name TEXT NOT NULL UNIQUE,
    url TEXT,
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

CREATE TABLE authors (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    whakoom_id INTEGER UNIQUE,
    name TEXT NOT NULL,
    url TEXT,
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

CREATE TABLE series (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    whakoom_series_id INTEGER NOT NULL UNIQUE,  -- from /ediciones/{id}
    slug TEXT NOT NULL UNIQUE,
    url TEXT NOT NULL UNIQUE,
    name TEXT,
    original_title TEXT,
    publisher_id INTEGER REFERENCES publishers(id),
    status TEXT,                                -- Terminada / En curso / ...
    format TEXT,                                -- Rústica con sobrecubierta / ...
    language TEXT,
    volumes_count INTEGER,                      -- "N cómics"
    rating REAL CHECK (rating IS NULL OR (rating >= 0 AND rating <= 5)),  -- verify scale in Phase 0
    rating_count INTEGER CHECK (rating_count IS NULL OR rating_count >= 0),
    rating_distribution TEXT,                   -- JSON {"5": 56, "4": 19, ...} (percentages)
    ownership_count INTEGER CHECK (ownership_count IS NULL OR ownership_count >= 0),
    synopsis TEXT,                              -- "Argumento"
    scrape_status TEXT NOT NULL DEFAULT 'pending'
        CHECK (scrape_status IN ('pending','completed','failed')),
    scraped_at TEXT,
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
    updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE INDEX idx_series_status ON series(scrape_status);
CREATE INDEX idx_series_publisher ON series(publisher_id);

CREATE TABLE series_observations (              -- append-only history
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    series_id INTEGER NOT NULL REFERENCES series(id) ON DELETE CASCADE,
    run_id INTEGER NOT NULL REFERENCES scrape_runs(id),
    observed_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
    rating REAL,
    rating_count INTEGER,
    rating_distribution TEXT,
    ownership_count INTEGER,
    volumes_count INTEGER,
    status TEXT,
    UNIQUE (series_id, run_id)                  -- idempotent per run
);
CREATE INDEX idx_observations_series ON series_observations(series_id);

CREATE TABLE volumes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    volume_slug TEXT NOT NULL UNIQUE,           -- token from /comics/{token}/...
    series_id INTEGER NOT NULL REFERENCES series(id) ON DELETE CASCADE,
    number INTEGER,                             -- NULL = tomo único
    title TEXT,
    publisher TEXT,                             -- denormalized for analytics convenience
    cover_url TEXT,
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE INDEX idx_volumes_series ON volumes(series_id);

CREATE TABLE series_authors (
    series_id INTEGER NOT NULL REFERENCES series(id) ON DELETE CASCADE,
    author_id INTEGER NOT NULL REFERENCES authors(id) ON DELETE CASCADE,
    role TEXT NOT NULL DEFAULT 'author',        -- author / guion / dibujo / ...
    PRIMARY KEY (series_id, author_id, role)
);

CREATE TABLE list_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    list_id INTEGER NOT NULL REFERENCES lists(id) ON DELETE CASCADE,
    position INTEGER NOT NULL,
    volume_slug TEXT NOT NULL,                  -- token from /comics/{token}/...
    whakoom_publication_id INTEGER,             -- data-item-id attribute, when parseable
    volume_url TEXT NOT NULL,
    volume_number INTEGER,                      -- NULL = tomo único
    publisher TEXT,                             -- denormalized from the list page
    series_id INTEGER REFERENCES series(id),    -- filled by Stage 3
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
    updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
    UNIQUE (list_id, position),
    UNIQUE (list_id, volume_slug)
);
CREATE INDEX idx_list_items_series ON list_items(series_id);
CREATE INDEX idx_list_items_list ON list_items(list_id);
```

### 8.4 Migrations

- Files: `store/migrations/NNN_description.sql`, applied once, in filename order, each in its own transaction, tracked in `_migrations`.
- Fresh start: `001_initial_schema.sql` is the file above. Legacy migration files belong to the legacy package and are **not** carried over.
- Forward-only. If the schema must change destructively, dump → rebuild → reload.

### 8.5 Named queries — convention

`store/queries/lists.sql` example:

```sql
-- name: upsert_list
INSERT INTO lists (whakoom_list_id, name, url, user_profile, description, comic_count, likes)
VALUES (?, ?, ?, ?, ?, ?, ?)
ON CONFLICT(whakoom_list_id) DO UPDATE SET
    name = excluded.name,
    description = excluded.description,
    comic_count = excluded.comic_count,
    likes = excluded.likes,
    updated_at = strftime('%Y-%m-%dT%H:%M:%SZ','now');

-- name: get_pending_lists
SELECT * FROM lists WHERE scrape_status != 'completed' ORDER BY id;
```

The loader splits files on `-- name:` markers; repositories call `db.query("lists", "upsert_list", params)`.

## 9. HTTP layer

`http/session.py` — a single shared `httpx.Client`:

- Sync client, `follow_redirects=True` **by default**; the resolver explicitly uses `follow_redirects=False` per-request to inspect `Location` headers.
- Politeness: sleep `WK_DELAY_SECONDS + uniform(0, WK_JITTER_SECONDS)` between requests, enforced inside the client wrapper so no caller can bypass it.
- Retry via `tenacity`: only on `httpx.TimeoutException`, `httpx.ConnectError`, HTTP 429 and 5xx; max `WK_MAX_RETRIES` attempts; exponential backoff 2 s → 4 s → 8 s. 4xx responses (≠429) are permanent failures.
- Cookie jar: when `WHAKOOM_COOKIE_FILE` is set, load it with `http.cookiejar.MozillaCookieJar` and pass it to the client. The jar is only *needed* for Stage 3 but sharing one client keeps fingerprinting consistent.
- `http/policy.py`: fetches and caches `robots.txt` at session start. Public stages assert each path is allowed before requesting. Stage 3's gated path is a documented, config-gated exception (§11, §19).

## 10. Pipeline stages

Each stage: is a CLI command; opens its own DB connection; creates a `scrape_runs` row and closes it (`completed`/`failed`/`aborted`); selects its own pending work from DB state (idempotent + resumable); archives raw responses when `WK_SAVE_RAW=1`.

```
wk lists          → lists index        → lists
wk list-detail    → list pages + POST  → list_items
wk resolve        → gated, cookie      → list_items.series_id + series stubs
wk series         → ediciones pages    → series + volumes + authors + observations
wk validate       → hard gate          → console report, exit code
wk analyze        → DuckDB             → views, notebook data, exports
```

### Stage 1 — `lists` (public)

- `GET https://www.whakoom.com/{profile}/lists/`.
- Parse each list card: `whakoom_list_id` (from URL suffix `..._<id>`), `name`, `url`, `description`, `comic_count`, `likes`.
- Upsert via `upsert_list`. New or content-changed lists get `scrape_status = 'pending'`; completed lists are left completed unless `--reset` is passed.

### Stage 2 — `list-detail` (public)

For each pending list (or `--list-id` / `--all`):

1. `GET` the list page → parse the first 50 server-rendered items.
2. Paginate (contract in §22): `POST /lists/listdetail.aspx/SeriesPage` with `{"id": <whakoom_list_id>, "f": 0, "p": <page>}` until `ExtraInfo == "0"`.
3. Per item, parse: `position` (running order across pages), `volume_url`, `volume_slug` (token from `/comics/{token}/...`), `whakoom_publication_id` (`data-item-id` attribute when present), `volume_number` (`"Vol. N"` → N; `"Tomo único"` → NULL), `publisher` (from the item's description span).
4. **Reconcile once per list after all pages are fetched**: `replace_list_items` deletes the list's stored rows and inserts the freshly fetched set, preserving previously resolved `series_id` links via the slug→series map (V2 §8.3 `list_items`). The fetched list is the version of truth — items removed from the list between runs are deleted, and `position` swaps never collide with `UNIQUE (list_id, position)`. The delta (`removed_slugs`, counts) is logged as a WARNING and recorded in `scrape_runs.notes`; the stage proceeds regardless (latest version wins).
5. Compare parsed count vs. `lists.comic_count`; mismatches are logged and surfaced by validation (§12) — never silently accepted.
6. Mark the list `completed` in the same transaction as its final batch.

If any pagination page fails permanently, the list stays non-`completed`. A partial list is never marked done.

### Stage 3 — `resolve` (authenticated; see §11)

For each `DISTINCT volume_slug` where `series_id IS NULL`:

1. Primary: `POST /pwkws.asmx/QuickView` with `{"cid": "comic{volume_slug}"}` → extract the `/ediciones/{id}/...` link. The resolver is **name-aware**: when the QuickView card (or a 200 fallback body) carries the series title, it is captured in the `SeriesRef`; the pure redirect fallback yields no name without a second request, so `series.name` stays NULL (schema allows it, §8.3) until Stage 4 fills it.
2. Fallback: `GET /comics/{volume_slug}/...` with `follow_redirects=False` → if `Location` contains `/ediciones/{id}`, use it; if 200, parse the parent-series link from the page.
3. If any response is a redirect to `/login`: **abort the whole stage** immediately with `session expired — re-export cookies`. Nothing is lost; re-running resumes.
4. Upsert a stub `series` row (`whakoom_series_id`, `slug`, `url`, `name` when known, `scrape_status='pending'`, `ON CONFLICT(whakoom_series_id) DO NOTHING`), then set `list_items.series_id` for all items with that slug.
5. Slugs that fail resolution are written to `data/review_unresolved.csv` and counted in the run record; the stage still completes.

This stage is the **entire authenticated footprint**: exactly one request per unique series.

### Stage 4 — `series` (public)

For each series where `scrape_status != 'completed'` (or `--force`):

1. `GET /ediciones/{whakoom_series_id}/{slug}`.
2. Parse (Spanish labels; verify selectors against fixtures in Phase 0):
   - `name` (h1), `original_title` (when shown), `publisher` (link under the title → `publishers`), `status` (`Terminada`/`En curso`), `format`, `language`
   - `volumes_count` (`"N cómics"`), `synopsis` (`"Argumento"`)
   - `rating` (`"4,3"` → `4.3`), `rating_count` (`"N votos"`), `rating_distribution` (star-bar percentages), `ownership_count` ("how many have it" — selector to confirm in Phase 0)
   - `authors` (from `/autores/{id}/...` links; role from credit labels, default `author`)
   - `volumes`: per-volume `volume_slug`, `number`, `title`, `publisher`, `cover_url`
3. One transaction per series: upsert publisher → series → volumes → authors/junction → **insert one `series_observations` row** → set `completed`.
4. Optional/missing fields are nulled and logged, never row-fatal. Required-field failures (no h1, no volumes block) mark the series `failed` and continue.

### Stage 5 — `validate` — see §12.  ### Stage 6 — `analyze` — see §14.

## 11. Login & resolution strategy

- The owner logs into Whakoom **once in a browser** and exports cookies to a Netscape-format `cookies.txt` (any "Get cookies.txt"-style extension). Path configured via `WHAKOOM_COOKIE_FILE`.
- **No automated credential login** — the site runs reCAPTCHA Enterprise; cookie import is both simpler and more robust.
- The cookie session is used **only** by Stage 3. All other stages are anonymous, public, and robots-allowed.
- Session expiry is detected (redirect to `/login`) and aborts the stage loudly; the pipeline is resumable, so recovery is: re-export cookies → re-run `wk resolve`.
- Stage 3 additionally requires `WK_ALLOW_GATED_RESOLUTION=1`, making the robots-exception an explicit, opt-in decision recorded in config.
- **Phase 0 probe (optional, ~30 min):** check `sitemap.xml`, slug-only `/ediciones/{slug}` URLs, and list-page HTML for embedded series links. If any publicly maps volume token → series ID, Stage 3 becomes anonymous and the cookie requirement disappears.

## 12. Validation gate

`wk validate` runs read-only checks and exits non-zero on failure. `wk analyze` refuses to run after a failed validation unless `--force` is passed.

Checks:

1. Per list: parsed item count vs. advertised `comic_count` (tolerance 0).
2. `PRAGMA foreign_key_check` — zero violations.
3. No duplicate `(list_id, position)` or `(list_id, volume_slug)` (enforced by schema; this double-checks).
4. Unresolved `list_items` count → reported; > 0 is a warning, not a failure (they're in `review_unresolved.csv`).
5. Ratings within 0–5; all counts ≥ 0 (also schema-enforced).
6. Row-count deltas vs. the previous successful run — unexpected drops flagged.
7. Parse-failure rate per stage below 5%.

Output: console report + summary written into the current `scrape_runs.notes`.

## 15. Testing strategy

All tests run **offline**. Fixtures are real snapshots harvested from the raw archive (§13).

- **Parser unit tests** — one fixture per case: lists index; list page 1; `SeriesPage` JSON fragment; terminal page (`ExtraInfo = "0"`); ediciones multi-volume; ediciones tomo único; ediciones with missing optional fields; series with multiple authors/roles. Assert every field, comma-decimal parsing, and pagination termination.
- **Dedup/idempotency tests** — same series in two lists → one `series` row, two `list_items`; two volumes of one series in one list → two `list_items`, one `series`; re-running any stage produces zero new rows and zero constraint errors.
- **Integration tests** — stages 1→4 end-to-end against `httpx.MockTransport` + a temporary SQLite file; resolver covers redirect, parent-link, and session-expired-abort paths.
- **Migration test** — `001` applies cleanly on a fresh DB; runner skips already-applied files.
- Commands: `uv run pytest` · `uv run ruff check .` · `uv run mypy .` · `uv run bandit -r whakoom_scraper/` · `uv run pre-commit run --all-files`.

## 18. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Site HTML/endpoint changes | Parsers isolated in `scrapers/`; fixture tests detect drift; raw archive enables instant re-fixturing |
| Cookie expiry mid-run | Loud abort + resumable stage |
| Rate limiting / IP block | 1.5 s + jitter politeness, tenacity backoff, honest UA; full runs are ~2–4 h and infrequent |
| Resolution gaps (unusual pages) | Two resolver paths; unresolved slugs exported for manual review |
| SQLite lock contention | Single writer per stage; WAL mode |
| Selector variance across ediciones pages | Defensive parsing; optional fields null-logged, never row-fatal |
| `SeriesPage` endpoint contract changes | Contract isolated in one adapter function with fixture tests |

## 19. Ethics & compliance

- Bulk scraping runs on **public, robots-allowed** pages at a polite rate with an honest user agent.
- **Stage 3 uses an authenticated session against `/comics/`, which `robots.txt` disallows.** This is a deliberate, owner-approved tradeoff for a single-user personal/research project, gated behind `WK_ALLOW_GATED_RESOLUTION=1` and limited to one request per unique series. The README must state this plainly.
- No secrets in code or git; the cookie file path lives in `.env` (gitignored).
- Personal/educational use; the README notes the project depends on Whakoom's current HTML and may need updates when the site changes.

## 20. Deferred features

Designed-for but **not built** in V2.0:

1. **List classification & canonical magazine names.** `lists.list_type` / `lists.canonical_name` stay NULL until populated from a small hand-maintained `config/lists.toml` (66 lists — manual curation is realistic and more honest than parsing names), optionally aided by an external source for canonical Japanese magazine names.
2. **External enrichment** (AniList GraphQL, Jikan/MAL). Matching strategy: exact title → normalized (lowercase, strip diacritics) → search fallback with a stored `match_confidence`; below-threshold matches exported for manual review. Would arrive as a new `series_enrichment` table via migration `002`.
3. **Async HTTP** — trivial later upgrade given the `httpx` client wrapper, unwarranted at current scale.

## 21. Explicitly out of scope

- Legacy data migration (database is rebuilt from scratch by re-scraping).
- Parquet snapshot infrastructure, content-addressed provenance stores, atomic publish pipelines — the observation table covers the history requirement at a fraction of the cost.
- A language-neutral "work" entity, cross-source entity resolution, sales estimation, a web UI, an API, scheduling/cron, multi-user support, image downloading, distributed crawling.

## 22. Appendix: URL anatomy & endpoint contracts

### URL anatomy

```
List index:    https://www.whakoom.com/{profile}/lists/
List page:     https://www.whakoom.com/{profile}/lists/{slug}_{whakoom_list_id}
Volume page:   https://www.whakoom.com/comics/{volume_slug}/{series_slug}/{number}
               (anonymous → 302 /login?ReturnUrl=...; robots-disallowed)
Series page:   https://www.whakoom.com/ediciones/{whakoom_series_id}/{series_slug}
               (public; series_slug matches the volume URL's series_slug segment,
                but the numeric whakoom_series_id is only exposed via gated pages)
Author page:   https://www.whakoom.com/autores/{whakoom_id}/{slug}
```

### List pagination contract (verified 2026-08-01)

```
POST https://www.whakoom.com/lists/listdetail.aspx/SeriesPage
Content-Type: application/json; charset=utf-8

{"id": <whakoom_list_id:int>, "f": 0, "p": <page:int>}

→ 200 {"Html": "<li>…</li>", "ExtraInfo": "<next_page:int as str>" | "0"}
```

- Page 1 (first 50 items) comes from the server-rendered list page HTML.
- `f` must be the **number** `0` (a string `""` causes HTTP 500).
- `ExtraInfo == "0"` terminates pagination.
- Works anonymously with plain HTTP; no cookies, tokens, or headers beyond `Content-Type`.

### Series page parsing targets (verified example: `/ediciones/673392/rosen_blood`)

| Field | Source on page | Example |
|---|---|---|
| name | h1 | "Rosen Blood" |
| publisher | link under h1 | "Panini Comics España" |
| volumes_count | "N cómics" | "5 cómics" → 5 |
| status | inline | "Terminada" |
| authors | "Autores" / credit links | "Kachiru Ishizue" |
| synopsis | "Argumento" | "Después de sufrir un accidente…" |
| rating | inline | "4,3" → 4.3 |
| rating_count | "N votos" | "16 votos" → 16 |
| rating_distribution | star bars | 5★ 56%, 4★ 19%, … |
| ownership_count | "lo tienen" block | **selector to confirm in Phase 0** |
| volumes | `/comics/{token}/{slug}/{n}` link list | numbers, titles, covers |
